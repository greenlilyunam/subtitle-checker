# P1 测试样例说明

## 1. 默认规则输出

输入：`localization-input.srt`  
配置：启用全部默认规则，不导入自定义术语表  
操作：接受全部低风险和中风险建议  
预期：导出内容与 `localization-expected-default.srt` 完全一致

除文本外，还必须断言：

- 14 个字幕块数量不变
- 序号不变
- 所有开始、结束时间码不变
- 第 14 条仍为两行，换行位置不变
- URL、邮箱和 `SmartInspect V2.1` 字面值不变

说明：默认配置没有声明 `思倍云` 是品牌保护词，因此通用字符转换会得到 `思倍雲`。这是有意设计，用来证明产品不能猜测所有专有名词。

## 2. 自定义术语覆盖

输入：`localization-input.srt`  
术语表：`../glossary/example-glossary.csv` 或 JSON 等价文件  
操作：接受全部可接受建议  
预期：导出内容与 `localization-expected-custom-glossary.srt` 完全一致

重点断言：

- `报警信息` 使用自定义 `告警資訊`，覆盖内置 `警示資訊`
- `视频监控` 整体使用 `影像監控`，不产生 `影片監控`
- `后台` 使用 `管理平台`
- `工单` 使用 `事件工單`
- `点击这里` 使用 `點選這裡`
- 受保护品牌 `思倍云` 保持简体官方写法
- 停用的 `视频→視訊` 条目不参与匹配

## 3. 已是台湾繁体

输入：`already-zh-tw.srt`  
配置：默认规则  
预期：

- 不产生会继续改变文本的建议
- 可以显示“没有发现需要本土化处理的内容”
- 直接导出时文本、序号和时间码不变
- 再次导入导出仍相同，用于验证幂等性

## 4. 无效术语表与冲突

术语表：`../glossary/invalid-glossary.csv`

预期导入摘要：

- `报警信息` 是有效条目
- 缺少源词的行无效
- `replace` 缺少目标词的行无效
- `action=auto` 的行无效
- `priority=150` 的行无效
- `账号→帳號` 的完全重复行被去重
- `工单` 存在相同最高优先级的两个不同目标词，标记为冲突
- 用户可以选择“使用有效条目继续”

结合 `glossary-conflict-input.srt` 运行时：

- 第 1 条产生高风险术语冲突
- 不自动选择 `事件工單` 或 `維修單`
- 该条不能批量接受
- 用户选择其中一个目标词后才可接受
- 第 2 条可以使用有效的 `报警信息→告警資訊`

## 5. 歧义表达

输入：`ambiguous-expressions.srt`

预期：

- `视频会议` 不应机械得到 `影片會議`。系统应将该项作为中风险歧义提示，允许用户选择或手动改为 `視訊會議`。
- `物理连接` 不应无条件套用网络语境的 `連線`，应提示或保留 `連接`。
- 导入示例术语表后，`一键` 命中 `warn` 条目，仅警告不改文字。
- `报警信息` 仍可独立产生术语建议。

这组样例要求实现上下文例外或风险拦截，不要求引入 AI 语义判断。

## 6. 用户状态与导出

在任一输入上分别测试：

- 接受：导出建议文本
- 忽略：导出原字幕
- 手动编辑：导出编辑文本
- 待处理：导出原字幕，并计入导出警告
- 撤销：恢复上一个状态和文本
- 重做：恢复被撤销的状态和文本

混合状态导出后，重新导入文件应能正常解析。

## 7. 重新运行检查

1. 手动编辑任一字幕。
2. 修改术语表或规则开关。
3. 点击重新运行检查。

预期：

- 系统不静默丢弃手动编辑
- 弹窗提供取消、保留编辑后重跑其余字幕、全部重跑三种选择
- 选择“保留编辑”后，该字幕文本保持，其他建议按新配置重算
