# P1 本土化规则说明

本文件是实现和测试的权威规则。若页面文案、PRD 示例或视觉稿与本文件冲突，以本文件为准。

## 1. 基本原则

1. 本土化不是无边界改写。不得改变事实、语气强度、产品能力和句子数量。
2. 原字幕始终保留，所有变化以建议形式产生。
3. 用户接受或手动编辑后，变化才进入导出结果。
4. 自定义术语表高于内置术语，保护项高于所有替换。
5. 序号、时间码、字幕块顺序和换行默认不改变。
6. 无法确定唯一表达时，提示而不自动替换。
7. 同一输入和配置必须得到稳定、可重复的结果。

## 2. 支持范围

首版仅支持：

- 源：简体中文（中国大陆），语言代码 `zh-CN`
- 目标：繁体中文（中国台湾），语言代码 `zh-TW`
- 输入/输出：UTF-8 SRT

混入英文、数字和技术标识是允许的，但不翻译英文句子。

## 3. 处理管线

每个字幕块按照以下顺序处理。实现不得随意调整顺序。

### 第 1 步：解析并保存不可变原文

- 复用 P0 的 SRT 解析能力。
- 为每条字幕保存 `originalText`。
- 不在原对象上修改文本。

### 第 2 步：识别并保护内容

默认保护：

- URL：`https://example.com/path?a=1`
- 邮箱：`ops@example.com`
- 版本号：`V2.1`、`v3.0.4`
- 纯型号/代码：`RTX 4090`、`IPC-302A`
- HTML/字幕标签（若 P0 已支持）：例如 `<i>...</i>` 的标签本身
- 自定义术语表中动作是 `protect` 的完整词语

保护表示内部处理时使用占位符，最终恢复原始字面值。保护项内部不做字符转换、地区词替换或空格改写。

品牌名和产品名只有在术语表明确设置为 `protect` 时才受保护，工具不能猜测所有专有名词。

### 第 3 步：匹配自定义术语表

- 只处理 `enabled=true` 的条目。
- 优先匹配更长的源词，避免短词破坏长词。
- 相同源词存在多个条目时，先比较 `priority`，数值越大优先级越高。
- 同一源词、相同最高优先级却有不同目标词时，生成高风险冲突，不执行替换。
- `protect`：保护命中内容，优先级最高。
- `replace`：生成可接受的替换建议。
- `suggest`：生成中风险建议，不允许默认批量接受。
- `warn`：不改文本，只生成检查提示。

匹配边界：

- 中文词按连续子串匹配。
- 英文词默认按完整单词匹配，区分大小写与否由字段控制；本示例格式未提供大小写字段时，默认不区分大小写。
- 不允许对已经被保护的片段再次匹配。

### 第 4 步：通用简体转台湾繁体字符

- 将未被保护、未被自定义术语完整替换的中文内容转换为台湾繁体字符。
- 使用离线、确定性的转换器，不得发送到网络服务。
- 转换器必须封装在独立适配层，便于测试和替换。
- 单纯字符转换归类为低风险。
- 不得依靠转换器直接决定所有地区词汇，地区词汇由下一步处理。

### 第 5 步：内置地区与企业用语

内置词表至少覆盖随包样例中的词。推荐初始规则如下：

| 简体/大陆用语 | 台湾繁体建议 | 动作 | 风险 | 说明 |
| --- | --- | --- | --- | --- |
| 软件 | 軟體 | replace | 低 | 通用软件语境 |
| 通过 | 透過 | replace | 低 | 方法或渠道语境 |
| 硬盘 | 硬碟 | replace | 低 | 计算机语境 |
| 信息 | 資訊 | replace | 低 | 信息内容/系统信息 |
| 数据 | 資料 | replace | 低 | 数据内容；数据库另设词条 |
| 数据库 | 資料庫 | replace | 低 | 长词优先 |
| 网络 | 網路 | replace | 低 | 互联网/网络连接语境 |
| 视频 | 影片 | replace | 中 | 若特指视频流，可由用户保留原词 |
| 摄像头 | 攝影機 | replace | 中 | 监控硬件语境 |
| 接入 | 介接 | suggest | 中 | 系统或设备整合语境 |
| 默认 | 預設 | replace | 低 | 软件设置语境 |
| 支持 | 支援 | replace | 低 | 功能支持语境 |
| 用户 | 使用者 | replace | 低 | 软件产品语境 |
| 账号 | 帳號 | replace | 低 | 登录语境 |
| 登录 | 登入 | replace | 低 | 账号登录语境 |
| 后台 | 管理後台 | suggest | 中 | 仅在管理系统语境 |
| 打开 | 開啟 | replace | 低 | 开启页面或功能的 UI 语境 |
| 点击 | 點選 | replace | 低 | UI 操作语境 |
| 这里 | 此處 | suggest | 中 | 可根据句子保留“這裡” |
| 连接 | 連線 | replace | 中 | 网络连接语境；物理连接可能不同 |
| 移动端 | 行動版 | suggest | 中 | 可依产品规范改为行動裝置版 |
| 电脑端 | 電腦版 | suggest | 中 | 避免强行补充平台含义 |
| 算法 | 演算法 | replace | 低 | 技术语境 |
| 识别 | 辨識 | replace | 低 | AI/图像识别语境 |
| 检测 | 偵測 | replace | 中 | 设备/系统检测语境 |
| 创建 | 建立 | replace | 低 | 建立工单、账户等 |
| 生成工单 | 建立工單 | suggest | 中 | 工作流创建语境，长词优先 |
| 报警信息 | 警示資訊 | suggest | 中 | 企业术语可能要求“告警資訊” |
| 记录 | 紀錄 | replace | 低 | 名词/动词均可提示 |
| 运维 | 維運 | replace | 低 | IT/设备运维语境 |
| 联系 | 聯絡 | replace | 低 | 联系人员 |
| 访问 | 前往 | suggest | 中 | URL 场景；其他语境不一定适用 |
| 邮件 | 電子郵件 | suggest | 中 | UI/正式文案 |
| 部署 | 部署 | protect | 低 | 台湾企业技术语境可接受，不强行改写 |
| 工单 | 工單 | replace | 低 | 仅字符转换 |

注意：

- 词表不是语言真理，只是 P1 的可测试默认配置。
- 产品应展示原因和来源，允许用户忽略。
- 自定义术语表可以覆盖这些规则。
- 长词优先，例如先匹配“数据库”，再匹配“数据”。

#### 上下文例外（不需要 AI）

以下固定搭配应在普通短词规则之前匹配：

- `视频会议`：不得套用 `视频→影片` 得到 `影片會議`；生成中风险提示，建议用户选择 `視訊會議` 或手动编辑。
- `物理连接`：不得套用网络语境的 `连接→連線`；保留字符转换后的 `物理連接`，并可显示说明。
- `网络连接`：可以建议为 `網路連線`。

实现可使用明确的例外词表和长词优先规则，不需要引入 AI 语义判断。

### 第 6 步：表达与格式规则

首版只做以下确定性调整，不做自由改写：

1. 连续的拉丁字母/数字技术词与相邻中文之间增加一个半角空格，例如 `AI算法` → `AI 演算法`、`IT运维` → `IT 維運`；受保护内容内部不处理。
2. 中文与 URL、邮箱之间的原有合理空格保留，不在 URL 或邮箱内部增加空格。
3. 连续两个及以上普通半角空格压缩为一个，但不处理受保护片段内部。
4. 中文顿号、逗号、句号、问号、感叹号保持全角。
5. 不自动改变引号样式；只在风险检查中提示混用。
6. 不改变字幕换行。若一条字幕包含多行，对每行处理后按原换行拼回。

### 第 7 步：风险扫描

生成建议后扫描：

- 是否还存在启用词表中的 `warn` 条目。
- 是否存在同优先级术语冲突。
- 是否存在明显未转换的简体字符（仅限已配置的检查集合，避免假阳性）。
- 是否出现目标词重复，例如 `管理管理後台`。
- 是否误改了保护内容。
- 是否出现空文本。

风险扫描只生成提示，不擅自重写。

### 第 8 步：合并建议

同一字幕块可能命中多个规则。UI 默认显示一张字幕卡片和一个合并后的建议文本，同时列出全部命中原因。

- 用户接受字幕卡片时，接受该卡片当前建议的全部低/中风险改动。
- 用户可以进入“查看详情”，逐项关闭某个建议，系统重新计算卡片建议文本。
- 若包含高风险冲突，卡片不能被批量接受。

## 4. 优先级与冲突顺序

从高到低：

1. 自定义 `protect`
2. 自定义术语的最高 `priority`
3. 自定义 `replace` / `suggest` / `warn`
4. 内置保护规则
5. 通用字符转换
6. 内置地区与企业用语
7. 格式规则
8. 风险扫描

若自定义术语明确命中整段内容，其目标词不应再次被内置词表二次替换。

## 5. 术语表格式

### 5.1 CSV

编码：UTF-8。首行必须是字段名。

必填字段：

- `source_term`
- `target_term`（`warn` 和 `protect` 可为空；`replace` 和 `suggest` 不可为空）
- `action`

可选字段：

- `note`
- `enabled`：`true` / `false`，默认 `true`
- `priority`：0–100 的整数，默认 50

### 5.2 JSON

顶层可以是数组，或 `{ "entries": [...] }`。字段使用与 CSV 对应的 snake_case 名称。

### 5.3 导入校验

以下情况为无效行：

- 缺少 `source_term`
- `action` 不在 `replace|suggest|protect|warn` 中
- `replace` 或 `suggest` 缺少 `target_term`
- `priority` 不是 0–100 的整数
- CSV 无表头或编码无法读取

空白行忽略。重复且内容完全一致的行只保留一条并提示去重。

## 6. 用户操作与导出语义

- `accepted`：导出建议文本。
- `edited`：导出用户手动编辑后的文本。
- `ignored`：导出原字幕。
- `pending`：导出原字幕，并在导出弹窗计入未处理数量。
- 高风险冲突处于 `pending` 时，导出前必须二次确认。

重新运行检查时：

- 若规则或术语表发生改变，旧建议失效。
- 用户已手动编辑的内容不能静默丢失。
- 应弹窗询问：取消、保留手动编辑并重新检查其余字幕、或全部重新检查。

## 7. 必测规则

1. 受保护的 `思倍云`、`SmartInspect V2.1`、URL 和邮箱保持字面值不变。
2. 默认词表把 `软件` 建议为 `軟體`。
3. 默认词表把 `报警信息` 建议为 `警示資訊`。
4. 自定义词表可把 `报警信息` 覆盖为 `告警資訊`。
5. `数据库` 必须整体变为 `資料庫`，不能出现错误的局部结果。
6. 相同源词、相同最高优先级、不同目标词产生冲突，不自动替换。
7. 输入已经是台湾繁体且没有命中警告规则时，不生成虚假问题。
8. 多行字幕处理后仍保持相同行数与换行位置。
9. 幂等性：对默认预期输出再次运行相同规则，不应继续产生新的文本变化。
10. 所有导出保持原时间码和字幕块顺序。
