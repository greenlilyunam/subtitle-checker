# P1 产品需求文档：台湾繁体本土化检查

文档状态：可开发  
适用产品：字幕检查器  
依赖版本：P0 已完成  
目标版本：P1 / V2  
目标平台：桌面端网页

## 1. 产品背景

P0 已经解决字幕交付前的机械检查问题，包括 SRT 解析、标点与空格处理、英文句首大写、结构检查、逐条确认、手动编辑和导出。

实际字幕工作中，还存在另一类耗时任务：已经有简体中文字幕，但交付给台湾地区客户时，不能只做字符层面的“简转繁”。部分词语、软件界面表达、标点习惯和技术术语需要按当地使用习惯调整；品牌名和客户指定术语又不能被通用规则误改。当前常见做法是人工逐句修改、搜索替换，或把字幕交给通用大模型后再次核对，容易出现漏改、过度改写、术语不一致和时间轴被破坏。

P1 在 P0 的“规则检查＋人工确认”框架上增加台湾繁体本土化能力，重点不是生成一份看似流畅的新文案，而是提供可控、可解释、可复核的修改建议。

## 2. 目标用户

主要用户：

- 需要向台湾地区客户交付宣传片、产品演示或培训视频的新媒体运营人员
- 负责简繁字幕版本管理的文案、内容运营或本地化人员
- 需要保持时间轴不变，只替换字幕文本的视频剪辑人员

首版不面向专业影视译员和大型语言服务团队，也不提供翻译项目管理能力。

## 3. 核心使用场景

1. 用户已有一份简体中文 SRT，需要快速生成台湾繁体交付版本。
2. 公司要求“软件→軟體、信息→資訊、网络→網路”等词语统一。
3. 客户要求某些产品功能名称保持指定写法，不能被通用规则覆盖。
4. 用户希望确认每一项本土化修改，不接受工具直接重写整份字幕。
5. 用户需要在不改变序号、时间码和字幕切分的前提下导出新文件。

## 4. 产品目标

### 4.1 用户目标

- 减少逐句查找简体字和地区用语的机械工作。
- 能够看见每处修改的原因和规则来源。
- 能够用企业术语表控制最终用词。
- 在导出前确认工具没有误改品牌、链接和技术标识。

### 4.2 产品目标

- 建立一条可验证的“导入—设置—检查—确认—导出”本土化流程。
- 复用 P0 的字幕解析、问题状态、差异对照、撤销和导出能力。
- 验证目标地区规则和自定义术语表是否能显著降低人工修改量。

### 4.3 不以此版本证明的目标

- 不证明 AI 翻译质量。
- 不承诺所有台湾表达都有唯一正确答案。
- 不替代母语审校或客户最终审核。

## 5. 产品定位

P1 是“已有译文/字幕的本土化检查器”，不是自动翻译平台。

一句话描述：

> 将简体中文字幕转成可逐条复核的台湾繁体本土化建议，并用企业术语表控制用词。

## 6. 核心流程

1. 用户进入字幕检查器。
2. 选择“本土化”模式。
3. 上传一个有效的 `.srt` 文件。
4. 系统解析字幕，默认识别源语言为“简体中文”。
5. 用户确认目标地区“中文（台湾）”，选择规则，并可导入术语表。
6. 用户点击“开始本土化检查”。
7. 系统在浏览器本地生成修改建议和问题列表。
8. 用户按问题类型筛选，逐条接受、忽略或手动编辑，也可以批量处理低风险建议。
9. 用户查看剩余未处理项与术语覆盖情况。
10. 用户导出 UTF-8 编码的 `_zh-TW.srt` 文件。

## 7. P1 功能范围

### 7.1 模式选择

- 在现有产品中新增“基础检查”和“本土化”两个任务入口。
- P0 基础检查保持原有行为。
- 选择“本土化”后显示本地化设置，不改变 P0 默认规则。

### 7.2 语言与地区设置

首版固定支持：

- 源语言：简体中文（中国大陆）
- 目标语言：繁体中文（中国台湾）

界面可以使用选择器呈现，但其他语言应显示为不可用或不出现，不能伪装成已经支持。

### 7.3 本土化规则

支持以下规则组：

1. 简体字转繁体字
2. 台湾地区常用词
3. 软件与企业场景用语
4. 台湾繁体标点与空格规范
5. 未转换字符与疑似大陆用语检查
6. 品牌、链接和技术标识保护

具体边界见 `LOCALIZATION-RULES.md`。

### 7.4 企业术语表

用户可以导入 UTF-8 CSV 或 JSON 术语表。

术语表至少支持：

- 源词
- 目标词
- 处理动作：替换、建议、保护、警告
- 备注
- 启用状态
- 优先级

功能要求：

- 导入前校验字段和数据。
- 显示有效条目数、无效条目数和冲突条目数。
- 无效行不得阻止其他有效行使用。
- 用户可以查看本次任务中的术语条目。
- 用户可以临时启用或停用单条术语。
- 用户可以新增、编辑和删除本次会话中的术语。
- 刷新页面后不要求保存；不建设云端术语库。
- 自定义术语表优先于内置地区用语规则。

### 7.5 检查结果

每个建议至少包含：

- 字幕序号和时间码
- 原字幕
- 建议字幕
- 差异高亮
- 问题类型
- 修改原因
- 规则来源：自定义术语、内置术语、字符转换或格式规则
- 风险等级：低、中、高
- 当前状态：待确认、已接受、已忽略、已手动编辑

### 7.6 确认操作

- 单条接受
- 单条忽略
- 手动编辑建议文本
- 选择多条后批量接受或批量忽略
- 撤销和重做
- 重新运行本土化检查

批量接受限制：

- 默认只允许批量接受低风险项。
- 中风险项需要二次确认。
- 高风险或冲突项不得一键批量接受。

### 7.7 导出

- 导出 UTF-8 SRT。
- 默认文件名：`原文件名_zh-TW.srt`。
- 保留原序号、时间码、排序和字幕块数量。
- 已接受和手动编辑的内容进入导出文件。
- 已忽略和未处理的内容保留原文。
- 导出不覆盖原文件。
- 导出前展示：已接受、已忽略、已编辑、未处理和冲突数量。
- 若仍有冲突项，允许导出，但必须明确警告并由用户确认。

## 8. 问题类型与风险等级

| 类型 | 示例 | 默认风险 |
| --- | --- | --- |
| 字符转换 | `数据` → `資料` 中的简繁转换部分 | 低 |
| 地区用词 | `软件` → `軟體` | 低 |
| 企业/技术用语 | `接入` → `介接` | 中 |
| 表达调整 | `点击这里` → `點選此處` | 中 |
| 标点与空格 | `AI算法` → `AI 演算法` | 低 |
| 术语表替换 | 用户指定 `报警信息` → `告警資訊` | 取决于条目，默认低 |
| 保护项 | 品牌名、URL、邮箱、型号保持不变 | 低 |
| 歧义/冲突 | 同一源词命中两个相同优先级目标词 | 高 |
| 疑似漏改 | 结果中仍存在配置的大陆用语 | 中 |

## 9. 页面范围

P1 不新建独立站点，在 P0 页面上增量增加：

1. 上传页的任务模式选择
2. 本土化设置面板
3. 本土化检查工作台状态
4. 术语表管理抽屉/侧栏
5. 术语表导入结果弹窗
6. 本土化导出确认弹窗
7. 无建议、术语冲突、导入失败等状态

具体布局与交互见 `P1-UI-SPEC.md`。

## 10. 数据与技术边界

- 沿用 P0 的 React、TypeScript、Vite、Tailwind CSS 和 Vitest 技术栈。
- 所有处理在浏览器内完成。
- 不使用后端、数据库、账号系统或外部 AI API。
- 不把字幕和术语表上传到服务器。
- 可以新增经过项目许可的离线简繁转换依赖，但转换逻辑必须封装为可替换适配器，并用本文件包中的样例测试。
- 不能用一串散落在组件里的 `replace()` 实现业务规则。
- 本土化引擎、术语表解析、冲突解决和 UI 状态应分层。
- 原字幕对象必须保持不可变；建议结果和用户接受后的结果分开保存。

建议的数据模型：

```ts
type LocalizationAction = 'replace' | 'suggest' | 'protect' | 'warn'
type LocalizationRisk = 'low' | 'medium' | 'high'
type LocalizationStatus = 'pending' | 'accepted' | 'ignored' | 'edited'

interface GlossaryEntry {
  id: string
  sourceTerm: string
  targetTerm: string
  action: LocalizationAction
  note?: string
  enabled: boolean
  priority: number
  source: 'custom' | 'builtin'
}

interface LocalizationIssue {
  id: string
  subtitleId: string
  originalText: string
  suggestedText: string
  type: string
  reason: string
  source: 'custom-glossary' | 'builtin-glossary' | 'character' | 'format' | 'conflict'
  risk: LocalizationRisk
  status: LocalizationStatus
  matchedTerms: string[]
}
```

以上为语义要求，不强制覆盖 P0 已有类型。Codex 应先检查现有代码，再以兼容方式扩展。

## 11. 成功指标

开发验收指标：

- 样例字幕的默认预期输出完全一致。
- 导入自定义术语表后，覆盖输出完全一致。
- 导出文件重新导入 P0/P1 后可以正常解析。
- 处理前后字幕块数量、序号和时间码完全一致。
- 受保护内容无误改。
- lint、单元测试和生产构建通过。

后续用户测试指标（不作为代码验收的虚构结论）：

- 5 名目标用户中至少 4 名能在无指导情况下完成一次本土化导出。
- 与纯手工搜索替换相比，单份字幕处理时间下降。
- 用户能解释自定义术语与内置规则谁优先。
- 用户在导出前能发现并处理高风险冲突。

## 12. P1 明确不做

- 英文、日文等语言翻译
- 原句自由改写或营销润色
- 自动判断客户品牌语气
- 视频、音频上传和语音识别
- 字幕时间轴调整
- 双语字幕排版
- 登录、历史记录和跨设备同步
- 云端术语库、审批流和多人协作
- 剪映、Premiere 或 Final Cut 插件
- 会员与付费

## 13. 仍需未来验证的判断

- 用户是否更需要“纯字符转换”还是“地区表达建议”。
- 用户能否理解低、中、高风险划分。
- CSV 是否是目标用户最方便的术语表格式。
- 自定义术语的典型规模是几十条还是上千条。
- 同一企业是否需要多个客户/地区术语配置。
- 用户是否愿意允许 AI API 参与更自然的表达改写。

这些判断不阻碍 P1 开发，但不能在作品集中写成已经验证的事实。
